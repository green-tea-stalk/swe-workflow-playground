# 要件定義書: 国際化対応（i18n）

本文書は、掲示板アプリケーションにおける国際化（i18n: Internationalization）の機能要件および非機能要件を定義します。すべてのユーザー向けインターフェースおよびシステムメッセージにおいて、日本語（`ja`）および英語（`en`）の両言語ユーザーに対するシームレスな多言語サポートを実現します。

---

## 1. 背景と動機（Context & Motivation）

### 1.1 課題の説明（Problem Statement）
現在の掲示板アプリケーションは、静的ユーザーインターフェース（UI: User Interface）要素、フォームラベル、および操作メッセージのすべてが日本語のみで表示されており、日本語を母語としないユーザーにとって利用困難な状態となっています。さらに、バックエンド API の入力バリデーションおよび問題詳細（Problem Details）レスポンスは固定のメッセージで提供されており、クライアントの言語設定に適応していません。利用範囲を拡大し、一貫した国際化体験を確立するために、本アプリケーションは UI 表示、クライアントへのエラーフィードバック、およびロケールに応じたフォーマット表示にわたる包括的な二言語対応を必要としています。

### 1.2 ビジネス目標および技術目標（Business & Technical Goals）
- **二言語アクセシビリティ**: 日本語（`ja`）および英語（`en`）の両方でアプリケーションの完全な利用可能性を提供し、英語を正式なデフォルトロケールとして位置付ける。
- **クライアント主導のロケール適応**: UI からの動的なユーザー言語選択、およびクライアントリクエスト設定に基づく自動ロケールネゴシエーションをサポートする。
- **ロケール対応のデータ表示**: 選択されたロケールの文化的フォーマット規約に準拠して、時間的メタデータ（投稿日時など）を表示する。
- **安全なエラーメッセージの多言語化**: クライアントから要求された言語にローカライズされた入力バリデーションエラー詳細および操作通知を提供し、サポート外の言語にはデフォルトロケールへ安全にフォールバックする。
- **投稿内容の真正性の保持**: ユーザーが投稿したコンテンツ（投稿者名、タイトル、メッセージ本文）は、自動翻訳や変更を一切行わず、入力された元の形式のまま厳密に維持する。

### 1.3 対象者・アクター（Target Personas & Stakeholders）
- **英語話者のエンドユーザー**: フィードを閲覧し、西洋形式の日時を読み、メッセージを投稿し、すべてのバリデーションフィードバックを英語で受け取る。
- **日本語話者のエンドユーザー**: フィードを閲覧し、日本標準形式の日時を読み、メッセージを投稿し、すべてのバリデーションフィードバックを日本語で受け取る。
- **API クライアント / 外部コンシューマー**: 言語設定ヘッダーを付与して HTTP リクエストを送信し、それに応じてローカライズされた構造化エラーフィードバックを受け取る。

## 2. ユーザーシナリオとユースケース（User Scenarios & Use Cases）

### 2.1 ユースケース 1: 手動での言語選択および切り替え（Manual Language Selection & Switching）
- **アクター**: エンドユーザー（英語話者または日本語話者）
- **事前条件**: 掲示板アプリケーションがブラウザに読み込まれていること。
- **トリガー**: ユーザーがアプリケーションツールバーの言語選択コントロールを操作する。
- **基本フロー（Basic Flow）**:
  1. ユーザーはツールバーのコントロールから別の言語（`English` または `日本語`）を選択する。
  2. システムは、新しく選択された言語設定をローカルストレージに永続化する。
  3. システムは即座にインターフェースを更新し、すべてのナビゲーションタイトル、フォームラベル、プレースホルダー、ボタン、投稿ゼロ時のプレースホルダー、およびページネーターコントロールを選択された言語で描画する。
  4. システムは、表示されているすべての投稿日時を選択されたロケールのフォーマット規約に一致するように更新する。
- **代替フロー（Alternative Flows）**:
  - ユーザーがすでにアクティブな言語を選択した場合: システムは変更を行わず、現在の状態を維持する。
- **事後条件**: UI が選択された言語で表示され、その設定は以降のアクセスでも維持される。

### 2.2 ユースケース 2: 初回アクセスおよび自動言語検出（Initial Access & Automatic Language Detection）
- **アクター**: 初回アクセスのエンドユーザー
- **事前条件**: ユーザーがこの端末・ブラウザで言語設定を行ったことがない（ローカルストレージに設定が存在しない）こと。
- **トリガー**: ユーザーがアプリケーションに初めてアクセスする。
- **基本フロー（Basic Flow）**:
  1. システムは、ユーザーのブラウザ言語設定を確認する。
  2. ユーザーの優先ブラウザ言語が日本語（`ja`）を示している場合、システムは UI を日本語で初期化する。
  3. ユーザーの優先ブラウザ言語が英語またはその他の言語を示している場合、システムは UI をデフォルト言語（英語）で初期化する。
  4. システムは、決定されたロケールに従って UI および投稿日時を描画する。
- **事後条件**: 決定されたロケールが有効になり、ユーザーの操作を受け付け可能な状態になる。

### 2.3 ユースケース 3: 多言語フォーム投稿およびバリデーションフィードバック（Multilingual Form Submission & Validation Feedback）
- **アクター**: メッセージを投稿するエンドユーザー
- **事前条件**: アプリケーションがユーザーのアクティブなロケールで表示されていること。
- **トリガー**: ユーザーが無効または不完全な入力を含む投稿フォームを送信しようとする。
- **基本フロー（Basic Flow）**:
  1. ユーザーは無効なデータ（必須項目の未入力や最大文字数超過など）をフォームに入力し、投稿を試みる。
  2. システムは無効な入力を検出し、アクティブなロケールでインラインバリデーションエラーメッセージを表示する。
  3. 操作レベルのエラーまたは API 障害が発生した場合、システムはアクティブなロケールでフィードバック通知（トースト / スナックバー）を表示する。
- **代替フロー（Alternative Flows）**:
  - ユーザーが有効なデータを入力して正常に投稿した場合: システムはアクティブなロケールで投稿成功の確認通知を表示し、フォームを初期化する。
- **事後条件**: ユーザーはローカライズされていないシステムエラーに遭遇することなく、アクティブな言語で実用的なフィードバックを受け取る。

## 4. 機能要件（Functional Requirements）

すべての機能要件は、標準的な EARS（Easy Approach to Requirements Syntax）パターンおよび大文字の RFC 2119 / RFC 8174 キーワードの日本語対応表現を使用して定義されています。

| 要件 ID | EARS パターン種別 | 仕様記述ステートメント（RFC 2119 / 8174 準拠） | 検証方法 |
| :--- | :--- | :--- | :--- |
| **REQ-001** | ユビキタス | システムは、すべての静的ユーザーインターフェース要素、操作メッセージ、およびシステム通知において、英語（`en`）および日本語（`ja`）の両言語をサポートしなければならない（MUST）。 | 自動テスト |
| **REQ-002** | ユビキタス | システムは、すべてのアプリケーションインターフェースおよびエラーフィードバック機構において、英語（`en`）を正式なデフォルト言語として指定しなければならない（MUST）。 | 自動テスト |
| **REQ-003** | イベント駆動 | ユーザーがツールバーの言語コントロールを介してアクティブな言語を変更したとき、システムはすべての静的インターフェーステキスト、ラベル、ヒント、エラーテキスト、およびボタンを選択された言語で即座に表示しなければならない（MUST）。 | シナリオテスト |
| **REQ-004** | イベント駆動 | ユーザーがツールバーの言語コントロールを介して言語設定を選択したとき、システムは選択されたロケールをブラウザのクライアントストレージに永続化しなければならない（MUST）。 | 自動テスト |
| **REQ-005** | 複合 | クライアントストレージに明示的な言語設定が存在する間、ユーザーがアプリケーションにアクセスしたとき、システムは保存されている言語設定を復元して UI を初期化しなければならない（MUST）。 | 自動テスト |
| **REQ-006** | 複合 | クライアントストレージに明示的な言語設定が存在しない間、ユーザーがアプリケーションにアクセスしたとき、システムは優先ブラウザ言語を検出し、優先ブラウザ言語タグが `ja` で始まる場合は日本語（`ja`）で UI を初期化し、優先ブラウザ言語タグが `ja` で始まらない場合は英語（`en`）で UI を初期化しなければならない（MUST）。 | 自動テスト |
| **REQ-007** | 複合 | フィード内に投稿を表示している間、投稿日時を提示するとき、システムは日付と時刻を日本語ロケール（`ja`）ではパターン `yyyy/MM/dd HH:mm:ss` を使用してフォーマットし、英語ロケール（`en`）ではパターン `MMM d, y, h:mm:ss a` を使用してフォーマットしなければならない（MUST）。 | 統合テスト |
| **REQ-008** | イベント駆動 | 投稿送信中に入力バリデーションエラーが発生したとき、システムはアクティブな言語でローカライズされたインラインバリデーションエラーメッセージおよびトースト通知を表示しなければならない（MUST）。 | 統合テスト |
| **REQ-009** | イベント駆動 | API クライアントが言語設定インジケーターを付与してリクエストを送信したとき、システムは要求されたロケールを評価し、その言語でローカライズされたエラーレスポンス（タイトル、詳細、およびパラメータ理由）を返却しなければならない（MUST）。 | 自動テスト |
| **REQ-010** | 望ましくない振る舞い | API クライアントがサポート外の言語を要求したか、言語設定インジケーターを省略した場合、システムはエラーレスポンスを英語にフォールバックしなければならず（MUST）、未解決のキーや未整形のメッセージ文字列を返却してはならない（MUST NOT）。 | 自動テスト |
| **REQ-011** | ユビキタス | システムは、ユーザーが投稿したコンテンツ（投稿者名、メッセージタイトル、およびメッセージ本文）を入力された元の形式のまま厳密に表示しなければならず（MUST）、自動翻訳やテキストの変更を適用してはならない（MUST NOT）。 | 自動テスト |

## 5. 非機能要件（Non-Functional Requirements）

- **NFR-PERF-001（言語切り替えの応答性）**: システムは、UI の応答性を損なうことなく、300ミリ秒以内に言語切り替え操作を完了しなければならない（MUST）。
- **NFR-USAB-001（視認性と人間工学）**: 言語選択コントロールは、すべてのビューポートにわたってプライマリアプリケーションヘッダー内に常時アクセス可能な状態で配置されなければならない（MUST）。
- **NFR-ACC-001（アクセシビリティ標準）**: ローカライズされたすべてのインターフェース要素、フォームコントロール、およびエラーバナーには、対応する言語でローカライズされた適切なアクセシビリティラベル（`aria-label`、`aria-live`、`role="alert"`）を含めなければならない（MUST）。
- **NFR-COMP-001（クロスブラウザ日時フォーマット）**: 日時のフォーマット処理は、サポートされているすべてのモダンブラウザ（Chromium、Firefox、WebKit）において、クライアント実行時エラーを発生させることなく一貫して動作しなければならない（MUST）。
- **NFR-REL-001（フェイルセーフなロケールフォールバック）**: ローカライゼーションリソースが欠落しているか解析エラーが発生した場合、システムは未処理の例外をスローしたり空の文字列を表示したりすることなく、正規の英語デフォルトテキストを表示して安全に停止（Fail-Closed / 安全側に倒す）しなければならない（MUST）。

## 6. スコープ外（Out of Scope）

以下の項目は、本仕様の対象外として明示的に除外されています。
- **ユーザーコンテンツの機械翻訳**: ユーザーが投稿したメッセージのタイトル、名前、本文の自動機械翻訳（Google 翻訳や AI 翻訳など）は対象外とし、投稿は投稿者の元の言語のまま維持されます。
- **第3言語への拡張**: 日本語（`ja`）および英語（`en`）以外の言語（中国語、スペイン語、フランス語、ドイツ語など）のサポートは、将来のマイルストーンへ延期します。
- **ユーザーアカウントごとの言語プロファイル管理**: リモートデータベース内のユーザープロファイルに言語設定を永続化すること（アプリケーションにユーザー認証やアカウント管理機能が存在しないため）は対象外とし、クライアント側のストレージのみを使用します。
